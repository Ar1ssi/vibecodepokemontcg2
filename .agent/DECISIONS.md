- D21 2026-09-10 [rules] Grand Tree's Stage-2-chain step re-resolves the Stage 1 host's live zone/index via `zoneOfInPlay(user, picked)` at pick time instead of reusing the pre-evolve `hostZone`/`hostIdx` closure vars — `evolveCard.js` keeps the base card in the zone array (marked `attached: true`) and inserts the evolution as a separate array entry, so a captured index/array-of-one snapshot from before the first evolve is not guaranteed to still describe where the Stage 1 card now lives. Both Grand Tree evolve-guard failure paths (deckIdx/hostIdx invalid) now `appendMessage` a reason instead of silently calling `finishGrandTree()` — the prior silent skip is indistinguishable from the user's report of a stage-2 card "disappearing". Root cause on the live PR96 (server-authoritative) repro is not 100% pinned from static reading alone; this is the concrete fragility found and the fix that removes it, plus gives a visible signal if it recurs.
- D20 2026-09-10 [rules-ui] `openAbilityChoicePicker`/`openCardPicker` has two valid usage patterns: (a) no `pickOnly`, no manual move in `onPick` — rely on the picker's own `zoneFrom`→`destination` auto-move (card-picker.js:652-661); (b) `pickOnly: true` with a manual `moveCardBundle` in `onPick`. Mixing them (destination set, no `pickOnly`, but `onPick` also moves manually) double-moves the card — the auto-move fires first, so the manual move's own zone-index lookup comes up empty and the handler bails. Fixed 4 sites in chat-buttons.js that mixed the patterns (Grand Tree's two pickers, and the generic stadium-evolve-search's two pickers it was split from) by adding the missing `pickOnly: true`.
- D19 2026-09-10 [rules-ui] Trainer-effect pickers whose candidate IS an in-play Pokémon (evolveStage2, devolve, switchOpponent/Own/Out, heal target, damageCounters target, attach-energy target, discardToolAndSpecialEnergy, swapWithDiscard host) now resolve via `openMatPick()` in trainer-execution.js — a click-on-the-real-mat-image picker (outline highlight + capture-phase document click/Escape to gate normal drag/click handling) — instead of the modal `openCardPicker` carousel. Hand/deck/discard/attached-item candidates (the Stage-2-from-hand step, search/discard pickers) are unchanged — they aren't rendered on the mat. User's explicit scope call: convert every in-play-Pokémon picker, not just Rare Candy's.
- D18 2026-09-10 [deck-builder] Energy tab in Browse Sets is a synthetic entry (`ENERGY_SET_ID = '__energy__'`), not a real TCGdex set: `fetchLegalEnergyCards` cross-references the global `/cards?category=Energy` summary list (id/localId/name only, no image) against each Standard-legal set's already-cached full record (which has `image` but no category) to build normalized cards, since neither TCGdex endpoint alone carries both fields. Placed last via `releaseDate: ''` rather than resorted, matching the user's requested tab position. The modern basic-energy reprint (Mega Evolution Energy / "mee" set) has NO `image` field anywhere in TCGdex (set record, card detail, or CDN path all 404) — `getModernBasicEnergyCards()` hardcodes its 8 cards with art hotlinked from `pkmncards.com/wp-content/uploads/mee_en_{localId}_std.jpg` instead (user's explicit call after TCGdex was confirmed to have no usable asset; verified cross-origin loadable from the app's own origin). The 8 gold secret rare "Basic {Type} Energy" cards are pulled individually by exact id from their original (now non-Standard) sets via `EXTRA_ENERGY_CARD_REFS`, since a blanket per-set sweep would also pull unrelated rotated-out special energies from those same sets.
- D16 2026-09-10 [netcode] `revealCards`/`hideCards`/`revealShortcut`/`hideShortcut` (I19) only ever flip `card.revealed` on the sender's own zone — no cross-player targeting was added, unlike legacy's honor-system `mouseClick.cardUser === 'opp'` path (opponent revealing your cards). `applyCommand` already only ever touches `draft.players[playerId]` (the sender), so this is free by construction, not an extra check; the opponent-targeted case is left ungated and keeps its old (already broken under authoritative rendering) direct-socket-emit behavior rather than being wired to a command that would need a new permission model. Matches D14's "server is sole arbiter of what a client may know" posture — letting player A force-reveal player B's secret zone contents would be a real capability, not a display toggle, and I19 didn't ask for one.
- D15 2026-09-09 [netcode] Printed card data (hp, attacks, types, weakness, resistance, retreatCost, stage) reaches the server as its own `cardStats` command, not as part of `loadDeck`. Deck rows carry identity only and the client resolves the rest from TCGdex asynchronously, so it cannot ride along with the deck load; `cardStats` addresses cards by `syncInstance` across every zone and updates in place, never rebuilding one, which is what makes it safe to arrive mid-game. The client is trusted for these values for the same reason it is already trusted for the deck list itself — D10's identity rule is untouched, since the server still mints every instanceId (I26).
- D14 2026-09-09 [netcode] The server is the sole turn authority under the flag: `apply-view.js`'s `reconcileTurnState` writes `rulesState.turnPlayer/turnNumber/phase` from every applied view, and no client-side path advances the turn. It deliberately does not dispatch `rules-turn-began` — `rules-bridge.js` hangs legacy knockout/deck-out adjudication off that event, which the server now owns (banner staleness tracked as I25). Cross-client parity is asserted over **public zones only** (`active`/`bench`/`discard`/`lostZone`/`board`/`stadium`), with owner-secret zones compared by count: per-recipient redaction (O4-A/I5) makes hand/prizes/deck contents structurally incomparable between two clients, so hashing them across clients can only ever false-positive (design 002 3.12, S65).
- D13 2026-09-09 [netcode] Live client-side zone reads under server-authoritative rendering (the 3.11 desync heartbeat, e2e API) go through `apply-view.js`'s own last-applied-view cache, not legacy `zoneArrays` (never populated post design-003, I15) and not `cardRegistry` (insertion-ordered, not view-ordered — would false-positive on hash comparisons). `deck` is excluded from the 3.11 comparison specifically: it's redacted to `{count}` even for its owner (O4-A/I5), so it can never be hashed for real; `hashState`/`hashBoardSnapshot` keep full deck fidelity for replay-harness/dual-run use (I24).
- D11 2026-09-09 [netcode] O4 gate ruled A — full authoritative rendering. Client renders only from server views; legacy DOM mutation deleted once parity lands. - D12 2026-09-09 [netcode] A `server_command` action gates its own legacy local-mutation body on `systemState.serverAuthoritative` at its entry point and builds hints from `apply-view.js`'s `cardRegistry`, never from legacy `zoneArrays` (design 003, O1-B/O2-B). When the command cannot be translated the gate fails OPEN — the action falls through to its legacy body — so an untranslatable action degrades to today's dual-run instead of silently vanishing.
- D10 2026-09-09 [netcode] Card identity across the dual-run boundary is translated, never punned: the server keeps minting instanceId and returns a per-player syncInstance→instanceId map at deck init; an unresolvable hint drops the command rather than guessing.
