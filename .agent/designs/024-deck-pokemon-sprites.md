# 024: Deck Pokémon sprites
Status: approved (user)
Date: 2026-09-22 · Session: S253

## Problem
Saved decks are distinguished only by a text name, so the My Decks bar and the editor header
read as an undifferentiated list. Pokémon TCG Live puts the deck's headline Pokémon beside its
name. The user asked for the option to pin 2–3 Pokémon to a deck and show their sprites next to
the deck name, in both regular and shiny.

## Constraints
- Sprite art: msikma/pokesprite `pokemon-gen8` (user-chosen source).
- Vendored into the repo (user decision): no runtime third-party dependency, works offline.
  GitHub is blocked for this session; jsDelivr is the only reachable mirror, so the vendoring
  script fetches per-file from jsDelivr.
- Placement (user decision): the editor's deck header AND the My Decks chips. The picker opens
  from the sprite strip next to the deck name — NOT a fourth Customize tab.
- New deck-record field must not break libraries saved before it (`parseLibrary` tolerance).
- Deck-builder styling rules go in `deck-builder-live.css` scoped under `.db-live` (D95).
- Pure model in `core/*.mjs`, DOM-only code in the renderer/UI files (D96).

## Options

**A. Sprite source** — (1) vendor all 905×2 gen-8 base sprites; (2) hotlink jsDelivr at runtime;
(3) vendor a curated subset and hotlink the rest.
- (1) ~1.5 MB / 1810 files in-repo; no runtime dependency; offline-safe.
- (2) zero repo weight; breaks if the CDN or upstream repo moves; nothing renders offline.
- (3) smallest repo delta but two code paths and a curation list to keep in sync.
**Pick: (1)** — the user chose it; it also matches the vendored coin scans and keeps the URL
builder a single pure function (`deckSpriteImageUrl`) with no fallback branch.

**B. Forms (mega / gmax / regional)** — include vs base forms only.
Including them multiplies the catalog ~1.6× and forces a two-level picker (species → form) for a
decoration. **Pick: base forms only** (905 species). Every species in `data/pokemon.json` was
verified to have a `gen-8` `$` form, so the catalog has no holes.

**C. Where the catalog lives** — hand-written list vs generated module vs fetch `pokemon.json`
at runtime. **Pick: generated module** (`pokemon-sprite-catalog.generated.mjs`, ~905 lines of
`{idx,name,slug}`), regenerated by `scripts/generate-pokemon-sprites.mjs`, matching the
`starter-decks.generated.mjs` precedent. A runtime fetch would re-add the dependency option A
just removed.

**D. Storage shape on the deck record** — `spriteSlugs: string[]` + a parallel shiny array, vs
`sprites: [{slug, shiny}]`. **Pick: `sprites: [{slug, shiny}]`** — shiny belongs to the slot, and
one array cannot drift out of sync with another.

**E. Picker placement** — Customize tab vs popover from the sprite strip.
**Pick: popover from the strip** (user decision): the control sits where its effect shows, and
the Customize tabs stay about board cosmetics.

## Design

### Data
Deck record gains `sprites: Array<{slug: string, shiny: boolean}>`, length 0–3, default `[]`.
`listDecks` projects it so the chips can draw without reaching into `library.decks`.

### `core/pokemon-sprite-catalog.generated.mjs` (generated — do not hand-edit)
`export const POKEMON_SPRITE_CATALOG = [{ idx: '001', name: 'Bulbasaur', slug: 'bulbasaur' }, …]`
905 entries, dex order. Produced by `scripts/generate-pokemon-sprites.mjs`, which also downloads
`client/src/assets/pokemon/gen8/{regular,shiny}/<slug>.png`.

### `core/deck-sprites.mjs` (pure)
```
MAX_DECK_SPRITES = 3
POKEMON_SPRITE_BASE_PATH = '/src/assets/pokemon/gen8'
findPokemonBySlug(slug) -> entry | null
searchPokemon(query, limit = 40) -> entry[]        // prefix hits before substring, dex order
deckSpriteImageUrl({slug, shiny}) -> string | ''   // '' for an unknown slug
normalizeDeckSprites(value) -> {slug, shiny}[]     // drops non-objects, unknown slugs and
                                                   // duplicates; caps at MAX_DECK_SPRITES
addDeckSprite(sprites, slug) -> {slug,shiny}[]     // no-op at max or on a duplicate
removeDeckSpriteAt(sprites, index) -> {slug,shiny}[]
toggleDeckSpriteShinyAt(sprites, index) -> {slug,shiny}[]
deckSpriteLabel({slug, shiny}) -> string           // 'Shiny Pikachu' | 'Pikachu'
```
All return new arrays; none mutate their input.

### `core/deck-library.mjs`
- `createDeckInLibrary(..., options)` reads `options.sprites`, stored via `normalizeDeckSprites`.
- `setDeckSprites(library, deckId, sprites)` — mirrors `setDeckSleeve`; stamps `updatedAt`.
- `saveDeckSnapshot` accepts `sprites`; `undefined` keeps, an array replaces (normalized).
- `parseLibrary` normalizes `sprites` on every deck it keeps, so a pre-S253 library and a
  hand-corrupted one both load as `[]` rather than throwing in the renderer.
- `listDecks` adds `sprites`.

### UI
- `renderDeckSprites({stripEl, sprites, editable, onOpenPicker})` in
  `native-deck-builder-renderers.js` — draws the strip (up to 3 `<img>`, plus a `+` affordance
  when editable and under the cap). Escapes everything; `alt` is the sprite label.
- `native-deck-builder-sprite-picker.js` — the popover: a search box over `searchPokemon`, a
  result grid of regular sprites, and the current slots with a per-slot shiny toggle and remove
  button. Reports changes through `onChange(sprites)`; owns no deck state.
- `native-deck-builder.js` — a `#nativeDeckBuilderDeckSprites` strip beside the deck name;
  changes go to `deckLibrary.setActiveSprites(target, sprites)` AND to the `chosenCosmetics`
  mirror keyed `sprites`, so Save carries them into a newly created deck exactly as sleeve/coin
  /mat do today.
- `native-deck-builder-library.js` — chips render a read-only strip before the name;
  `setActiveSprites` / `getActiveSprites` accessors added alongside the sleeve/coin/mat ones.
- `index.ejs` — `#nativeDeckBuilderDeckSprites` in the deck header row, and
  `#nativeDeckBuilderSpritePicker` as the popover host.
- `deck-builder-live.css` — `.native-deck-builder-deck-sprites`, `-sprite`, `-sprite-add`,
  `.native-deck-builder-sprite-picker*`, all under `.db-live`; sprites are `image-rendering:
  pixelated` so the 68px art stays crisp.

## Edge cases & failure modes
| # | Case | Expected behavior | Covered by |
|---|---|---|---|
| 1 | deck has no sprites (all pre-existing decks) | strip renders empty; chip shows name only; `+` still opens the picker in the editor | [ ] |
| 2 | stored `sprites` malformed (string, null, array of nulls, unknown slug) | `normalizeDeckSprites` drops it; deck still loads | [ ] |
| 3 | 0 / 1 / 3 / 4 sprites | 4th add is a no-op; `normalizeDeckSprites` truncates a stored 4+ to 3 | [ ] |
| 4 | same Pokémon added twice | second add is a no-op (dedupe by slug) | [ ] |
| 5 | sprite PNG missing / 404 | `<img>` `onerror` hides that image; name and the rest of the strip still render | [ ] |
| 6 | Save cancelled midway with sprites chosen and no deck loaded | nothing is written; the mirror keeps the choice for the next Save | [ ] |
| 7 | deck deleted while its sprites are on screen | chip disappears with the deck; editor detaches as today | [ ] |
| 8 | search query with no match / empty query | empty query lists dex order; no match shows an empty-state line | [ ] |
| 9 | name with regional characters (Nidoran♀, Flabébé, Type: Null) | catalog carries the display name; slug stays URL-safe | [ ] |
| 10 | localStorage write fails | `saveLibraryToStorage` already returns false silently; sprites behave like any other field | [ ] |

## Migration / rollout
No migration step. `sprites` is additive and absent-tolerant: `parseLibrary` fills `[]` for any
deck saved before this change, so an old library loads unchanged and a new one is readable by an
older build (which ignores the field). Revert path: drop the field readers; stored `sprites` keys
become inert. Vendored art is removable with `rm -r client/src/assets/pokemon`.
